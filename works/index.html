デザインカンプからの実装 3本

Adobe XD のデザインカンプを読み、数値どおりに HTML / CSS / JavaScript と WordPress オリジナルテーマに落とした練習制作物です。座標は目分量で寄せず、 XD ファイルから取り出した実測値と突き合わせて検証しています。

これはクライアント案件ではありません。 デザインカンプは Codejump の配布物で、 「練習で制作したサイトは自由にポートフォリオへ掲載してOK」と規約に明記されているものを使っています。 カンプに入っていた写真は配布元が出所を明示していないため、グレーのプレースホルダーに差し替えています。

  • 明るいHOUSE｜コーポレートサイト（固定サイドメニュー）

    元カンプ：Codejump 上級編 ／ PC 1400px・SP 375px ／ ブレークポイント 960px

    300px の固定サイドメニュー、スクロールしても残る固定背景の上を半透明のセクションが流れる構成、 画像を使わず CSS だけで組んだ矢印型のフローチャート。960px 以下では全画面ドロワーに切り替わります。

検証のしかた

`.xd` ファイルは中身が ZIP と JSON なので、パースして全要素の座標・色・ フォントサイズ・行送り・字送りを数値で取り出しました。それをヘッドレス Chromium で レンダリングした実装の getBoundingClientRect() と1項目ずつ突き合わせています。

形状は許容 ±1px、文字のベースラインは ±3px（LP は OS 標準フォント指定のため）
対象検査項目結果
コーポレートサイト（静的）122122 / 122 一致
WordPress テーマの出力122122 / 122 一致
ランディングページ141141 / 141 一致

横方向は 320 / 360 / 375 / 414 / 600 / 768 / 900 / 960 / 1000 / 1024 / 1100 / 1280 / 1400 / 1600 / 1920px で横スクロール 0 を確認。 1000px 付近は崩れの報告が最も多い幅なので必ず入れています。 実際、最初の実装ではここで 133px の横スクロールが出ていました。

カンプと指示書が食い違っていた6点（LPの背景ドット柄、リストの縦ピッチのばらつき、 見出し罫線の間隔、SPカードの文字溢れなど）は、カンプを正として実装し、 判断の理由を実装メモに残しています。
